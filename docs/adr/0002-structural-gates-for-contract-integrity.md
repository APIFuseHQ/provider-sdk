# ADR: Structural gates instead of remembered rules for SDK contract integrity

- Status: proposed
- Date: 2026-07-30
- Deciders: Taehoon (owner), Soju (agent)
- Scope: `@apifuse/provider-sdk` contract surface, its release pipeline, and its consumer verification
- Supersedes nothing; complements `0001-native-socks5-gateway-proxy.md`

## Context

Three failures in a single day of native-proxy work shared one shape: **a green gate measuring the wrong thing.**

1. **Dead contract.** `ProviderProxyPolicy.session.drainLeadSeconds` shipped in the TypeScript surface while `defineProvider`'s runtime allowlist still read `new Set(["affinity","lifetimeMinutes","poolSize"])`. 1157 SDK tests, lint, type-check, `pack:check/smoke/types`, and a green release guard all passed. The field was undeclarable by any real consumer. Found only when a provider repo was wired to the candidate (fixed in #88).

2. **Silent behavioral regression.** Deleting the kakaotalk `native-runtime.ts` bridge in favor of `createNativeNetworkClient` dropped a persistent post-connect `socket.setTimeout()`. Both implementations satisfy `NativeNetworkClient`, both type-check, all tests passed — but a peer that stays connected and silent now hangs the consumer forever, because the consumer's own deadline loops are parked inside `await connection.read()` (fixed in #89).

3. **Evidence/candidate race.** Release evidence is produced by hand from a local checkout and pasted into the PR body, while the guard requires the body to cite the current candidate SHA. Four consecutive validation rounds (25-30 min each) completed successfully and were each voided by an unrelated main merge re-cutting the candidate.

The remediation for all three was a written rule: a skill patch, a reference document, a prompt constraint. Written rules only work when a human or agent remembers to read them, and their cost recurs on every task forever.

Measured drift surface: `rejectUnknownFields` is called at **27 distinct sites** in `src/define.ts`, each with a hand-maintained literal allowlist. Every one of them is a place where the public type and the runtime validator can silently disagree, exactly as (1) did.

## Decision

Convert these three failure classes from remembered rules into structural gates. A structural gate is one that fails the build when violated, without anyone remembering it exists.

### 1. Type/validator agreement test (highest priority)

Add a meta-test that enumerates the public config surface and asserts every field survives a round trip through the public entry point (`defineProvider`), and that a deliberate typo still throws. New fields are covered automatically because the test derives its cases from the type/schema rather than a hand-written list.

Preferred long-term form is deriving both sides from one source (a schema as SoT, with `z.infer` for the type and `schema.keyof()` for the allowlist). Given 27 independently hand-written allowlists, that migration is incremental; the agreement test is the gate that makes the migration safe and closes the bug class immediately.

### 2. Transport conformance suite

Publish a shared test suite that every implementation of a runtime capability interface must pass: the SDK implementation, any provider-side bridge, and any test double. It encodes behavior the interface cannot express — idle timeouts, cancellation, close semantics, error classification.

Rationale: failure (2) was undetectable by type checking by construction. A conformance suite is the only mechanism that makes "swap implementation A for implementation B" provably behavior-preserving, and its value compounds as more native providers land.

### 3. Release evidence generated by CI at the candidate SHA

Move evidence production from a human/agent local run into the release-branch workflow. The workflow runs the gate chain on the candidate commit and records the result; the guard checks for a successful evidence run **at the current head** instead of parsing checkboxes in prose.

Rationale: evidence and candidate SHA become atomic by construction. A refreshed candidate regenerates its own evidence, so the merge-queue race disappears rather than being managed by freezes and re-runs.

### 4. Representative consumer smoke in SDK CI

Install the packed tarball into a representative consumer and run that consumer's gates as part of SDK CI.

Rationale: failures (1) and (2) were both found by a real consumer and by nothing else. "All package gates green" measures the package against itself; this job is what makes the release claim mean "usable", not merely "self-consistent".

### 5. Out of scope here: delegation diff-boundary enforcement

The same day produced a scope overrun where a two-secret mapping request became a 23-file generator redesign, and the required production diff turned out to be zero lines. The structural fix (declare allowed paths per delegation and machine-check the diff against them before reporting) belongs to the agent's own tooling, not this repo. Recorded here so the pattern is not mistaken for an SDK problem.

## Consequences

Positive:

- The three failure classes stop depending on anyone reading a skill or a reference.
- The migration toward schema-derived validation gets a safety net that makes it incremental instead of a big-bang refactor.
- Release throughput improves: no merge freezes, no re-validation rounds, no hand-pasted evidence.
- Consumer breakage is detected before publish rather than by the first consumer to adopt the release.

Negative / accepted:

- SDK CI gets slower and gains a dependency on a consumer repo. Mitigation: pin the consumer to a known-good ref and treat consumer-side unrelated failures as non-blocking, or vendor a minimal consumer fixture if the coupling proves fragile.
- A conformance suite is a public contract of its own; tightening it later is a breaking change for implementors.
- The release-guard rework touches the publish path, which is the highest-risk workflow in the repo. It must ship behind a period where both the old and new signals are observed.

## Rejected alternatives

- **Document the rules harder.** Already done today (skill patch + two references). It reduces recurrence but does not prevent it, and the cost recurs per task.
- **Rely on reviewer vigilance.** All three failures passed review and CI; two were found only by wiring a real consumer.
- **Big-bang migration to schema-derived validation across all 27 sites.** High blast radius on the validator that gates every provider, with no safety net until it lands. The agreement test must come first.
