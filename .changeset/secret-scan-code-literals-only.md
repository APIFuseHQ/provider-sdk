`apifuse submit-check`'s entropy secret scan now reads string literals in code only. Comments are removed with each file's own lexer before any quote is read: JS/TS sources use the TypeScript lexer (the comment ranges the other source lints already skip), so full-line `//` comments, trailing comments, and `/* … */` blocks never yield candidates, while a `//` inside a string, template, or regex is not mistaken for a comment. Shell sources (`.sh`/`.bash`, Dockerfile, entrypoint) treat a word-initial `#` outside quotes as a comment and backticks as command substitution rather than string delimiters. Before this, a backticked SDK identifier in a comment, such as `` `resolveHealthCheckInputDateTokens` ``, was read as a 33-character string literal whose own name supplied the secret-like context, and blocked submission at security 0/10. Detection in code is unchanged: quoted, single-quoted, and template literals (including multi-line templates) are still scanned, a trailing comment still counts as context for the literal on its line, the known token patterns still read README, `index.ts`, `package.json`, and fixtures in full, comments included, and a JS/TS file the lexer cannot parse is still scanned line by line, unmasked. No public API changes.
