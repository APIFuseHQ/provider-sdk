Classify a `ctx.http` request that a provider cancelled with its own `AbortSignal.timeout` as a timeout. Such a request rejects with `transport_cancelled`, which serve answered as `502` with category `upstream_http`, `retryable: false` and the message `Upstream request failed`, while the same limit set through the `timeout` request option is served as `transport_timeout` with `504` and category `timeout`. When the cancellation's cause is a `TimeoutError` and the served request's own signal has not aborted, serve now answers it like `transport_timeout`: `504`, category `timeout`, source `upstream_failure`, `retryable: true` in the response body, the `X-ApiFuse-Error-Observability` header and the `provider_request_failed` log, and the message `Request timed out`. The body code stays `transport_cancelled` and the `TimeoutError` stays the logged cause. This holds during the request, during a retry backoff, and while a streamed body is consumed, and on the stateful owner route, whose source pod's `HttpStatefulOwnerForwarder` now receives `transport_cancelled` with status 504 instead of 502. This is how a provider's own `AbortSignal.timeout` aborting `ctx.native` (`native_connection_aborted`) and `ctx.native`'s connect deadline (`native_connection_timeout`) are already served.

A provider abort with any other reason (`abort()`, `abort(reason)`) keeps `upstream_http`, `502` and `retryable: false`. A caller that closed the connection keeps `client_cancelled` and `400`, and a stateful forwarding deadline that expires mid-operation keeps `STATEFUL_FORWARDING_DEADLINE_EXPIRED`. No public API, category, source or status value changes.
