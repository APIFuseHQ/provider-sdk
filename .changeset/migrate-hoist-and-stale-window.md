`apifuse migrate` moves the two residues it used to leave by hand.

`errors-hoist` (new, runs after `errors-factory`): every `errorCodes` row written inline in an operation with its status or description moves into the provider's one `defineErrors` map (the existing `export const errors = defineErrors({`, else `domain/errors.ts`, created or appended to), the operation lists `errors: [errors.CODE, ...]` in the original order with the import, a code several operations list gets one entry, a registry-equal row becomes `CODE: sdkErrors.CODE`, and locale keys carry over. The pre-#238 `docs: { errorCodes }` block and a meta object spread into an operation are hoisted the same way. The entry serves what the legacy path served: the row's status, its retryable (else `false`), and the category the provider's throw sites agree on (else `upstream_rejected` for 409/410/422, else `provider_error`). What one entry cannot serve stays in `errorCodes` with a residue naming the fix: a registered code whose row differs from the SDK registry (`errors-hoist-sdk-row-conflict`), a code declared with different status, retryable or locale keys across operations (`errors-hoist-code-conflict`), a non-literal value, a spread that is not a map. Rows of one code that differ only in description take the first wording and note each dropped one.

`health-stale-window` (new, runs after `health-refs`): a per-call `staleIfErrorMs` on `ctx.cache.getOrSet` / `ctx.cache.set` becomes `cache: { staleIfErrorMs }` on every operation whose handler reaches the call (by name, through imports), the per-call option is deleted, a window named by a constant of another file is exported and imported, and the provider declaration gains `cache: true` when it lacks the capability. An operation that reaches two different windows (`health-stale-window-two-values`), a call no handler reaches, a declaration that disagrees, and a window that is not a number or a named constant are residues whose calls keep the option.

The `errors-factory` codemod's operation-list rule now skips an `errorCodes` list whose operation already has `errors`, and its `sdk-row-conflict` diagnostic reports table rows only (`errors-hoist` reports the inline ones). The `errors-factory-inline-row-hoist` and `health-stale-window-per-call` diagnostics are dropped from the report when the step that moves them runs in the same invocation. Both steps need the TypeScript compiler API the provider already installs for `apifuse check`.
