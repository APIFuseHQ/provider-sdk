`apifuse migrate` moves the two residues it used to leave by hand.

`errors-hoist` (new, runs after `errors-factory`): every `errorCodes` row written inline in an operation with its status or description moves into the provider's one `defineErrors` map (the existing `export const errors = defineErrors({`, else `domain/errors.ts`, created or appended to), the operation lists `errors: [errors.CODE, ...]` in the original order with the import, a code several operations list gets one entry, a registry-equal row becomes `CODE: sdkErrors.CODE`, and locale keys carry over. The pre-#238 `docs: { errorCodes }` block and a meta object spread into an operation are hoisted the same way. The entry serves what the legacy path served: the row's status, its retryable (else `false`), and the category the provider's throw sites agree on (else `upstream_rejected` for 409/410/422, else `provider_error`). What one entry cannot serve stays in `errorCodes` with a residue naming the fix: a registered code whose row differs from the SDK registry (`errors-hoist-sdk-row-conflict`), a code declared with different status, retryable or locale keys across operations (`errors-hoist-code-conflict`), a non-literal value, a spread that is not a map. Rows of one code that differ only in description take the first wording and note each dropped one. It also closes `errors-factory`'s by-hand import step: a file whose table became a map gets `import { defineErrors, sdkErrors }`; a file whose throw site or health scenario now names `errors.X` imports the provider map when it declares X, is retargeted to the map in its own scope that declares X (`SEARCH_ERRORS.X`), or is reported (`errors-hoist-reference-undeclared`) when no map does; a registered code a throw site names that no map in the file's scope declares is declared by value in the provider map, and a code exactly one map elsewhere declares gets that map imported. Rule 1 no longer rewrites a throw site of a code the SDK runtime owns (`MISSING_SECRET`, `reauth_required`, `HANDLE_*`, ...), for which no factory can exist, nor one that states a per-throw `messageKey`/`fixKey` (`errors-factory-throw-site-locale-key`), nor one whose `retryable`/`category` is a shorthand or a variable the codemod cannot check (`errors-factory-throw-site-dynamic-option`).

`health-stale-window` (new, runs after `health-refs`): a per-call `staleIfErrorMs` on `ctx.cache.getOrSet` / `ctx.cache.set` becomes `cache: { staleIfErrorMs }` on every operation whose handler reaches the call (by name, through imports), the per-call option is deleted, a window named by a constant of another file is exported and imported, and the provider declaration gains `cache: true` when it lacks the capability. An operation that reaches two different windows (`health-stale-window-two-values`), a call no handler reaches, a declaration that disagrees, and a window that is not a number or a named constant are residues whose calls keep the option.

Three `errors-factory` defects found by the fan-out pilot are fixed: an `errorCodes` list holding a row constant referenced by name (also from another file) was rewritten to `errors: []`, dropping the declared code; now the list rule skips any element that is neither a row literal nor a spread (`errors-factory-entry-not-a-row`) and `errors-hoist` resolves the name. A test-case array whose rows nest `{ code, status }` matched the table rule and became a non-compiling `defineErrors(...)`; now `apifuse migrate` never scans `__tests__/**`, `*.test.ts` or `*.spec.ts`, and only a direct array element whose own keys include `code` and `status` is a row. A throw site of a registered code whose per-throw `retryable` or `category` contradicts the registry was rewritten silently, flipping what the site serves; now the site keeps its legacy form and `errors-factory-throw-site-registry-conflict` names the two choices. A fourth, of the same family: the list rule spread a table whose rows state no status (`errorCodes: [...T]`, which the table rule never converts) as `...Object.values(T)` over an array, and the provider stopped loading; now the list rule leaves every list with a spread to `errors-hoist`, which spreads a name only when it is, or the table rule makes it, a `defineErrors` map, and reports the rest (`errors-hoist-spread-not-a-table`); `--only errors-factory` and `--only errors-hoist` therefore run both. The `errors-factory` codemod's operation-list rule also skips an `errorCodes` list whose operation already has `errors`, and its `sdk-row-conflict` diagnostic reports table rows only (`errors-hoist` reports the inline ones). The `errors-factory-inline-row-hoist` and `health-stale-window-per-call` diagnostics are dropped from the report when the step that moves them runs in the same invocation. Both steps need the TypeScript compiler API the provider already installs for `apifuse check`.
