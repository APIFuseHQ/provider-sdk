"@apifuse/provider-sdk": minor
---

`apifuse migrate` moves the two residues it used to leave by hand.

`errors-hoist` (new, runs after `errors-factory`): every `errorCodes` row written inline in an operation with its status or description moves into the provider's one `defineErrors` map (the existing `export const errors = defineErrors({`, else `domain/errors.ts`, created or appended to), the operation lists `errors: [errors.CODE, ...]` in the original order with the import, a code several operations list gets one entry, a registry-equal row becomes `CODE: sdkErrors.CODE`, and locale keys carry over. The pre-#238 `docs: { errorCodes }` block and a meta object spread into an operation are hoisted the same way. The entry serves what the legacy path served: the row's status, its retryable (else `false`), and the category every throw site of the code served (a literal per-throw `category`, or the serve default for a site without one: `upstream_rejected` for 409/410/422, `input_validation` for a 4xx `ValidationError`, else `provider_error`) when all served one value, else the serve default, never a majority. What one entry cannot serve stays in `errorCodes` with a residue naming the fix: a registered code whose row differs from the SDK registry (`errors-hoist-sdk-row-conflict`), a code declared with different status, retryable or locale keys across operations (`errors-hoist-code-conflict`), a non-literal value, a spread that is not a map. Rows of one code that differ only in description take the first wording and note each dropped one. It also closes `errors-factory`'s by-hand import step: a file whose table became a map gets `import { defineErrors, sdkErrors }`; a file whose throw site or health scenario now names `errors.X` imports the provider map when it declares X, is retargeted to the map in its own scope that declares X (`SEARCH_ERRORS.X`), or is reported (`errors-hoist-reference-undeclared`) when no map does; a registered code a throw site names that no map in the file's scope declares is declared by value in the provider map, and a code exactly one map elsewhere declares gets that map imported. Rule 1 no longer rewrites a throw site of a code the SDK runtime owns (`MISSING_SECRET`, `reauth_required`, `HANDLE_*`, ...), for which no factory can exist, nor one that states a per-throw `messageKey`/`fixKey` (`errors-factory-throw-site-locale-key`), nor one whose `retryable`/`category` is a shorthand or a variable the codemod cannot check (`errors-factory-throw-site-dynamic-option`), and in fact rewrites no throw site at all any more (`errors-factory-throw-site-option` names every site standalone): throw sites are `errors-hoist`'s, which reads every `new ProviderError` / `AuthError` / `ValidationError` site before anything is rewritten, fills the `category` each provider row of a converted table lacks (the one its sites served, and `retryable: false` where the category's default would flip the legacy default), rewrites a site to `errors.X({...})` only when the provider declares its code with one contract (across operations' rows, tables and maps) and that contract serves what the site served, and otherwise leaves it as written with a residue naming why (`errors-hoist-throw-site-conflict`, `errors-hoist-throw-site-code-conflict` with the contracts listed, `errors-hoist-throw-site-row-conflict`, `errors-hoist-throw-site-undeclared`, `errors-hoist-throw-site-shadowed`). A site the factory cannot replace (an `AuthError` / `ValidationError`, or a code the SDK runtime owns such as `MISSING_SECRET`) loses its per-throw `category` / `retryable` when they equal what the server serves without them (the declaration; the SDK's own value for a runtime-owned or registered code), so `legacy-error-options` has no user a migrated provider did not name; one that states another value, or a variable, stays and is named (`errors-hoist-throw-site-sdk-conflict`, `errors-hoist-throw-site-dynamic-option`); so does a subclass site whose code may still have a legacy `errorCodes` row after this run (a refused row, or a list left whole behind an unreadable spread), and one whose value the serving branch's no-declaration default would not serve (a site an auth flow reaches reads no declaration). A file whose own table is named `errors` rewrites its sites to that map and names the rest; only an exported `errors` map is the provider's. A registered-code row whose description the registry's replaces is noted (`errors-hoist-description-registry`). A `--dry-run` decides every site and declaration as the apply does. A subclass site that states no category is named when the declaration this run writes replaces the default it served under a legacy row (the declared category is served from then on). Only a table errors-factory converts stands for a map in a dry run and an array is never a map in the apply, so a `[...] satisfies T[]` table's sites are never rewritten to a call on an array (`throw-site-undeclared` names them, and dry run equals apply). An `errorCodes` the step cannot read (a call, a property access, a name that is not a map) is named (`errors-hoist-list-not-readable`) and keeps every subclass site's options, since the rows it hides would serve once they are gone. A defineErrors map spread into a plain array literal (which throws at import once errors-factory has converted the table) is named `errors-hoist-map-spread-in-array` with the `Object.values(MAP)` fix. A map another file must import is exported by the step (a plain top-level `const`), else the site is named and no import is written, so a migrated provider always links. A code two maps declare resolves through the map the same run imports, so the first run is the fixed point. Every row literal in the sources is read for a registered code departing from the registry; while any list's rows cannot be read, a registered code's site is left and named (`errors-hoist-throw-site-row-unknown`). A construction whose code is a variable and that sets a per-throw option is named (`errors-hoist-throw-site-dynamic-code`), so `apifuse migrate` exits 1 wherever `apifuse check` still counts a legacy-error-options user.

`health-stale-window` (new, runs after `health-refs`): a per-call `staleIfErrorMs` on `ctx.cache.getOrSet` / `ctx.cache.set` becomes `cache: { staleIfErrorMs }` on every operation whose handler reaches the call (by name, through imports), the per-call option is deleted, a window named by a constant of another file is exported and imported, and the provider declaration gains `cache: true` when it lacks the capability. An operation that reaches two different windows (`health-stale-window-two-values`), a call no handler reaches, a declaration that disagrees, and a window that is not a number or a named constant are residues whose calls keep the option.

Three `errors-factory` defects found by the fan-out pilot are fixed: an `errorCodes` list holding a row constant referenced by name (also from another file) was rewritten to `errors: []`, dropping the declared code; now the list rule skips any element that is neither a row literal nor a spread (`errors-factory-entry-not-a-row`) and `errors-hoist` resolves the name. A test-case array whose rows nest `{ code, status }` matched the table rule and became a non-compiling `defineErrors(...)`; now `apifuse migrate` never scans `__tests__/**`, `*.test.ts` or `*.spec.ts`, and only a direct array element whose own keys include `code` and `status` is a row. A throw site of a registered code whose per-throw `retryable` or `category` contradicts the registry was rewritten silently, flipping what the site serves; now the site keeps its legacy form and `errors-factory-throw-site-registry-conflict` names the two choices. A fourth, of the same family: the list rule spread a table whose rows state no status (`errorCodes: [...T]`, which the table rule never converts) as `...Object.values(T)` over an array, and the provider stopped loading; now the list rule leaves every list with a spread to `errors-hoist`, which spreads a name only when it is, or the table rule makes it, a `defineErrors` map, and reports the rest (`errors-hoist-spread-not-a-table`); `--only errors-factory` and `--only errors-hoist` therefore run both. The `errors-factory` codemod's operation-list rule also skips an `errorCodes` list whose operation already has `errors`, and its `sdk-row-conflict` diagnostic reports table rows only (`errors-hoist` reports the inline ones). The `errors-factory-inline-row-hoist` and `health-stale-window-per-call` diagnostics are dropped from the report when the step that moves them runs in the same invocation. Both steps need the TypeScript compiler API the provider already installs for `apifuse check`.
