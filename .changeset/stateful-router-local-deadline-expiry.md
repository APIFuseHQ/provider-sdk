Classify a stateful operation that the `StatefulSessionRouter`'s own deadline timer cancelled during local execution as the deadline expiring. The router arms a timer from the request's `deadlineAt` and hands its signal to the local executor; when that signal cancelled the operation, the failure reached the owner pod's internal route as whatever the session layer threw (a `transport_cancelled` read caused by the timer's abort reason, or a plain error), and the route recognised only its own deadline signal's reason, so the owner pod answered `502` with category `upstream_http`, or `500` `internal_error`, while the source pod answered `504 STATEFUL_FORWARDING_DEADLINE_EXPIRED` for the same deadline. A failure whose cause chain carries the router timer's own abort reason is now rethrown by the router as `StatefulRoutingDeadlineError` with that failure as its cause, exactly as the router already does for a forwarding request its timer aborted, and counted in `apifuse_stateful_provider_routing_deadline_expired_total`. The owner pod's internal route and the ordinary route therefore serve it as `STATEFUL_FORWARDING_DEADLINE_EXPIRED`: `504`, category `timeout`, source `apifuse`, `retryable: false`, with the cancelled read still visible in the logged cause chain.

A failure that does not carry the timer's reason keeps its own classification, including one thrown after the deadline fired: a provider's own `AbortSignal.timeout` abort stays on the provider timeout branch, a caller that left stays `client_cancelled`, and an upstream failure stays an upstream failure. The timer's abort reason keeps the name `AbortError`. No public API, category, source or status value changes.
