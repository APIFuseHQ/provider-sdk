**Breaking.** The one-release-window paths of the DX program are deleted. Each shape is now refused where it enters; the load-time refusals (`defineProvider`, `defineCursor` / `defineDraft`) are `ValidationError`s whose `fix` names the `apifuse migrate` step that rewrites the shape, and the codemods themselves stay.

- Per-throw error options. `new ProviderError(message, { code, category, retryable })` (and the same on `AuthError` / `ValidationError` and every other provider-facing class) throws `PER_THROW_ERROR_OPTIONS_RETIRED` at construction; `category` and `retryable` are gone from `ProviderErrorOptions`. The refusal is a provider defect the SDK detected and is served like `OUTPUT_VALIDATION_FAILED`: a platform fault (HTTP 500, `source: "apifuse"`, `retryable: false`, header `origin: "platform"`, category `internal_error`), never the caller's input failure; the body carries the code and the message that names the construction, and the author guidance (the `defineErrors` declaration and `apifuse migrate --only errors-factory`) goes to the `provider_request_failed` log line as the `per_throw_error_options_retired` signal. At the type level the two fields are `never` on the options every provider-facing constructor accepts (`ProviderErrorConstructorOptions` = `ProviderErrorOptions & RetiredErrorContractFields`), so tsc reports a per-throw value that arrives through a typed variable, a spread of a typed object, a helper parameter or a subclass `super()`, not only in an object literal; the runtime refusal stays as the backstop for JavaScript and casts. A provider code's status, category and retryability come from its declaration alone (`defineErrors`, or the still-read `errorCodes` row), so `resolveProviderErrorContract` no longer takes `legacyOptions`, the `provider_error_options_deprecated` server warning is gone, and the `legacy-error-options` lint rule is deleted; the table itself is still named by the new `deprecated-error-codes-table` warning of `apifuse check`. SDK-constructed errors (transport failures, session expiry, missing secrets, output validation, stream limits, handle errors) keep their own contract through an SDK-internal brand (`TransportErrorOptions`, `SessionExpiredError`, `HandleErrorOptions` and `ProviderSecretError` take `SdkErrorOptions`); the brand's writer and reader are not exported from any entry point, so provider code cannot launder a per-throw value through them, and a category outside the provider-failure domain on one of those classes is read as unset (served under the class's derived category, named by the `unknown_provider_error_category` log signal), as before. Served behaviour changes only for a provider throw that set one of the two options: it is refused instead of served. Fix: `apifuse migrate --only errors-factory`.
- Handle declaration. `fieldName` and `issuedBy` are gone from `DefineCursorOptions` / `DefineDraftOptions`; `defineCursor` / `defineDraft` throw `HANDLE_OPTION_RETIRED` when either is present. The key and the issuer come from the operation schemas only (no declared-option precedence, no issuer-disagreement warning); `legacyHandleOptionsOf` and `LegacyHandleOption` are removed from `handle/contract`, and the `legacy-handle-declaration` lint rule is deleted. Fix: `apifuse migrate --only handles`.
- `proxy.session.poolSize`. Gone from `ProviderProxyPolicy.session`; `defineProvider` throws `PROXY_POOL_SIZE_RETIRED` instead of warning. Fix: `apifuse migrate --only declaration`.
- Redundant approval. `defineProvider` throws `REDUNDANT_APPROVAL` when an operation's `approval` equals the `riskClass` default (`read -> never`, `write -> risk-based`, otherwise `always`); `defaultApprovalPolicy` is exported from `types` as the one definition. The `redundant-approval` lint rule is deleted. Fix: `apifuse migrate-operation-declaration .` removes an approval equal to the default.
- Context keys. The `context-keys-required` lint rule is deleted; an auth flow reading an undeclared `ctx.context` key is already refused at run time (`ContextAccessError`), which stays the one refusal.

Kept: the `errorCodes` table (still read, `@deprecated`). `description-key-required` is removed by its own change, which makes `descriptionKey` required on every operation.

Retired lint rule ids: `legacy-error-options`, `legacy-handle-declaration`, `redundant-approval`, `context-keys-required`.
