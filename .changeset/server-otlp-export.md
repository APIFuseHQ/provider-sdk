"@apifuse/provider-sdk": minor
---

Accept `APIFUSE__TRACE__EXPORTER=otlp` for server trace output and resolve the OTLP/HTTP export target from the standard OpenTelemetry environment contract.

- The server exporter list is now `console`, `json`, `otlp`, and `none`; the three existing values behave exactly as before, and an unknown value still warns once and fails closed to `none`.
- The endpoint resolves from `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` used verbatim, else `OTEL_EXPORTER_OTLP_ENDPOINT` as a base URL with `v1/traces` appended after the configured path (existing path bytes are preserved; only the separator is added). An explicit `TraceConfig.otlp.endpoint` still wins when a caller supplies one; the served-provider path is environment-only. Only an unset or empty variable counts as absent. The winning candidate must be an absolute http(s) URL without embedded credentials; an invalid or whitespace-only one fails closed rather than falling through to a lower-precedence destination.
- Headers resolve from `OTEL_EXPORTER_OTLP_TRACES_HEADERS`, else `OTEL_EXPORTER_OTLP_HEADERS`, in the `key=value,key2=value2` format with percent-decoded values. Header names merge case-insensitively, so an explicit `Authorization` replaces an environment `authorization` instead of being sent alongside it. A header name or value that cannot be sent disables export once instead of failing every batch.
- Resource attributes merge `OTEL_RESOURCE_ATTRIBUTES` under the SDK's per-request attributes, with `service.name` resolving from `OTEL_SERVICE_NAME`, else `OTEL_RESOURCE_ATTRIBUTES` (an explicit `service.name` passed by a caller wins over both). A malformed `OTEL_RESOURCE_ATTRIBUTES` value (including empty members or a trailing comma) is discarded as a whole and reported once, never applied partially.
- The OTLP environment variables are engine-owned: a provider cannot declare them as secrets, and they are filtered from the engine-managed provider environment projections (server runtime, `apifuse dev`, `apifuse record`), so collector credentials never reach `ctx.env.get()`. Engine-owned names are matched case-insensitively, so a mixed-case alias such as `otel_exporter_otlp_headers` is rejected and filtered as well, and the provider environment context never resolves such an alias.
- Export runs through the engine-bound transport: on Bun this is the read-only, non-configurable `Bun.fetch`, which no code in the process can replace, so replacing `globalThis.fetch` (even before the SDK is imported) cannot intercept collector credentials. On other runtimes the transport is the `fetch` seen when the SDK first loads. Code that already holds process authority (a preload, or provider code running in the same process) can still read `process.env` or patch other builtins; no in-process boundary prevents that. Queued export batches run in a detached engine async context rather than inheriting the request context that freed a slot. Failure warnings name only an HTTP status, `timeout`, or an allowlisted system error code; nothing from an error object, endpoint, or header is ever interpolated.
- Export batches flow through a process-wide bounded queue with a concurrency cap, a drop policy when the queue is full, and capped exponential retry for transient failures (HTTP 408/429/502/503/504, timeouts, network errors; certificate failures are dropped without retry). Each trace context hands every span to the exporter exactly once, so a request with several root spans no longer re-sends earlier spans. Drop warnings are rate-limited and carry counts instead of one line per batch, with a trailing summary once a burst ends. Provider operations are never affected: with no resolvable endpoint the server warns once and disables export, and export failures stay fire-and-forget with the existing bounded timeout; response bodies are cancelled while that timeout still applies.
- Spans exported by the server pass through the same sanitization as console output, so credentials recorded on spans are redacted before they leave the process. Per-request resource attributes get the same treatment; operator-configured attributes from the environment keep their values, with control characters neutralized and secret-named keys redacted. Export configuration is not reachable from the trace context handed to provider code.
- Each trace context now carries its own random trace id, so batches from one request share an id and separate processes can no longer collide.
- `TraceConfig.otlp.endpoint` is now optional, so `{ exporter: "otlp", otlp: { headers, timeout } }` type-checks; the server trace resolver fills a missing endpoint from `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` or `OTEL_EXPORTER_OTLP_ENDPOINT`. `CreateTraceContextOptions` gains an optional `sanitizeSpanForExport` hook that receives a detached copy of each span immediately before OTLP export; a hook that throws or returns nothing drops that batch. Programmatic trace contexts that do not set it are unchanged.
