Redact known request secrets before recording trace attributes and errors, emitting request and cleanup log messages, resolver diagnostics, and SSE errors. Reuse the self-test value collector at the server boundary for an explicit allowlist of resolved credentials, extended by existing per-call sensitiveParams. Keep state keys readable after redaction, omit browser cleanup stacks, and sanitize apifuse-perf span exports.

Following #149 decision D9, this needs no provider sensitiveValues or sensitivePathSegments declaration. The request registry also feeds record-time redaction so getSpans and onSpan are protected; existing output heuristics remain. The optional createTraceContext redact callback is additive and backward compatible. Perf exports also use the provider/env registry and existing per-call sensitiveParams, including low-entropy URL path credentials. Environment credentials and their compiled matchers are prepared once at server startup, and SDK env readers register live resolved credentials into the current request before use. Reads outside a request (including CLI and perf contexts) enter a shared process fallback composed with each app’s static inventory, using the same raw/trimmed/credential-component variants. The fallback caps retained values at 1,024 entries and 64 KiB; exhaustion emits one value-free warning and suppresses free-text diagnostics process-wide until restart. Independent runtime/configuration evaluations can use an internal fallback lifetime scope; apps retain that scope across awaits and after evaluation, without clearing other apps’ inventories. Request scopes finish on terminalization; timers born inside a request register later reads into the app’s existing fallback lifetime after its response, error, or stream termination. Reads while the request is live remain request-local. Request-local reads remain isolated; connection credentials and auth inputs are harvested before validation, and per-call declarations enrich only the request registry. Invalid or throwing callbacks emit a constant failure sentinel; an independent private matcher checks callback output for surviving secrets.

Unresolved percent escapes after three decode rounds suppress the entire field to `[REDACTION_FAILED]` only when the nonempty registry contains values eligible for percent-encoded matching. This includes unreserved ASCII encoded as `%HH`; empty and short-only registries do not suppress benign residue. Matching for values of at least eight characters covers base64/base64url (padded and unpadded), JSON escaping and Unicode NFC/NFD. Static, fallback and request registries refuse values shorter than four characters: no supported credential source requires these trivial values, whose common-token matches would erase unrelated IDs and diagnostics. Values of at least eight characters match case-insensitively; registered values of four to seven characters match only case-sensitive literal tokens, with no encoded variants. As an owner-visible policy, operator-critical structured fields (log codes, request IDs, routes, span names, trace IDs and HTTP status) match only values of at least eight characters; free text retains short token matching. Number, boolean and bigint attributes consult the registry only when their string form has at least eight characters; short numeric/boolean coincidences preserve their types (bigints retain their existing string normalization, with internal type provenance through export). Exhaustion suppresses free-text string attributes only; keys and typed values still check actual registered credentials without blanket suppression. The closed-enum attribute allowlist is outcome, code, errorClass, phase, cacheStatus, identitySource, taxonomy and taxonomyVersion; these also retain actual-credential matching. Nested credential harvesting is iterative, bounded to depth 8 and 64 KiB; exhausted budgets suppress free-text diagnostics to `[REDACTION_FAILED]`. Limitations: a secret split across separate attributes (for example `{left:"orch", right:"ard"}`) cannot be detected by a value matcher; credentials disclosed before a per-call declaration cannot be recalled. Changes deliberately favor emitting less over retaining potentially sensitive diagnostics.

Run the type-checked development benchmark with `bun run bench:redaction`.

The engine ceremony lease key and incoming or newly minted opaque handles also enter the registry. Raw HTTP error results retain their status-derived observability header and redact known credentials in status text. If status-text redaction fails closed during registry exhaustion, emit the standard HTTP reason phrase for that status (empty for an unknown status), preserving the HTTP contract without trusting the provider’s free text. Raw `Response` bodies are provider-owned and are not scanned; their bytes, streaming behavior, Content-Length, and Content-Encoding are preserved.

Redacted attribute keys use unique numbered sentinels to preserve cardinality. An OTLP batch is suppressed if its trace ID cannot be safely retained as hexadecimal text; a once-per-process, per-reason warning reports `unverifiable_trace_id` and the running dropped span count on the first drop, never the ID or attribute values. Subsequent drops update the process counter silently; the internal read-only `getDroppedOTLPSpanCount(reason)` accessor exposes the current total without a reset path. A throwing warning sink is swallowed, retaining both count and latch. Caches containing diagnostic text are request-local, and request matchers compile lazily with each value’s variants generated once.

Paired whole-request benchmarks (600 alternating pairs against beta.59, 20 declared secrets plus one connection secret) measured echo p50 overhead of 88.0–96.4 µs (22.7–24.2%); baseline p50 was 388.3–398.4 µs and redacted p50 was 487.5–495.9 µs. A seven-span resolver request using real SDK/CapSolver instrumentation with vendor I/O and polling delay stubbed measured 258.4–305.1 µs overhead (31.7–31.9%); baseline p50 was 814.6–956.0 µs and redacted p50 was 1083.9–1278.9 µs. One-minute host load was 37–38 during these final runs. These CPU-path measurements exclude external service latency. The 10% echo target remains unmet. Short ASCII fields skip impossible matches, invariant ASCII tokens avoid duplicate encoders, flat credential inventories avoid iterator frames, and numbered-key lookup allocation waits until a key changes; record-time checks and independent verification remain in place.
