Runtime boundary lint: `process-env-direct-read`, `node-runtime-module-import`, and `direct-fetch-call` are now **error** level. A finding fails `apifuse check` and `apifuse submit-check` — in the official mode and in the bounty `standalone` mode alike; this rule family does not take the standalone downgrade the self-hosted browser rule takes, because the bounty submit check is the one gate an external contribution passes before review, and a request path that reaches around `allowedHosts`, proxy policy, redaction, and the secret presence gate is exactly what that gate exists to catch.

The rules shipped at `warn` as a migration window; this release closes it. Before the promotion the live provider fleet was re-linted from each repository's committed `origin/main` (`git archive`, source text only, every non-archived `apifuse-provider-*` repository of the organisation). The request-path hits the warn release was announced for — E2E fake toggles, diagnostic taps, debug dumps, `Bun.file` artifact reads, engine-env probing — were removed or moved behind the SDK context. Two repositories still had a hit when this changeset was written and are handled outside this release: naver-map's ffmpeg captcha-audio preprocessing (`Bun.write` / `Bun.spawn` / `Bun.file`) is acknowledged with `@apifuse-allow` in apifuse-provider-naver-map#24 while the keep / delete / `ctx.stt` decision stays open in apifuse-provider-naver-map#20, and zozotown's remaining `process.env` reads leave with its SDK pin bump (apifuse-provider-zozotown#30). A provider that bumps to this release with an unacknowledged hit sees `bun run check` fail on the bump and fixes or acknowledges the finding in that same PR. Nothing changes at runtime; the escape hatch is unchanged: `// @apifuse-allow <rule>: <reason>` on the finding line or the line above moves the finding to the `INFO` audit lines and the check passes.

`apifuse check` no longer scans a directory under the provider root that is itself a git checkout — a linked worktree (`.worktree/<branch>/`, a `.git` file), a nested clone (`.git` directory), or an initialised submodule. Those files are another revision of some repository, not this provider's runtime source, and the tooling-directory exemption (`scripts/`, `tools/`, `bin/` at the root) does not apply inside them, so a stale worktree's `scripts/*.ts` used to be linted as request-path code and, at error level, would have failed the root `bun run check`. Git refuses to track a path named `.git`, so the marker cannot be committed to hide a file from the scan; `.agents`/`.apifuse` stay in scope as before.
