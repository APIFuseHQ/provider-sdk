smartproxy egress moves from the IP-extraction allocator to the vendor's gateway with a per-attempt session id, and the proxy pool is gone.

- `smartproxy` is now synthesized locally like NodeMaven: `<user>_area-<CC>_life-<minutes>_session-<id>` against `proxy.smartproxy.net:3120`, authenticated with the sub-account credentials `APIFUSE__PROXY__SMARTPROXY_USERNAME` and `APIFUSE__PROXY__SMARTPROXY_PASSWORD`. The extraction API, the 15 s extraction cache, the Redis singleflight lock and the stale-pool refresh pass are removed.
- **Breaking for deployments:** the SDK no longer reads `APIFUSE__PROXY__SMARTPROXY_APP_KEY`. A required smartproxy policy without the gateway pair fails with `PROXY_REQUIRED` naming the missing `APIFUSE__PROXY__SMARTPROXY_USERNAME` / `APIFUSE__PROXY__SMARTPROXY_PASSWORD`; a smartproxy-first chain fails over to the next vendor with `no_credentials`. The two new names are engine-owned, and the retired app key stays engine-owned so a pod that still receives it never exposes it to provider code.
- A rotating policy mints a random session id per attempt; a sticky policy derives `sid(affinityKey, lifetime window, attempt)`, so every process serving one connection shares one egress IP without shared storage, and a transport retry moves to the next session id instead of the next pool slot. The sticky window is wall-clock aligned for both vendors on every transport. smartproxy clamps `lifetimeMinutes` to 5..120 and reports the clamp in `diagnostics.lifetimeClamped`.
- **Breaking:** `ProviderProxyPolicy.session.poolSize` is removed; `defineProvider` rejects it as an unknown field. The vendor fallback chain no longer depends on a pool size: a request's attempt budget is split evenly across the declared vendors in order (`mapAttemptToVendor`: vendor `i` starts at `ceil(i × budget / vendors)`, so every vendor is reached whenever the budget is at least the chain length), and an implicit safe-method request is entitled to `PROXY_ATTEMPTS_PER_VENDOR` (3) attempts per vendor. The budget is the caller's explicit `retry.attempts` when one is pinned, on `ctx.http` and `ctx.stealth` alike.
- New vendor selector seam (`ProxyVendorSelector`, `getProxyVendorSelector`, `setProxyVendorSelector`, `staticOrderProxyVendorSelector`): the resolver asks the selector which vendor and session serve an attempt, and `ctx.http` and `ctx.stealth` report every attempt's outcome back to the same selector instance that served the request (`ProxyResolutionOptions.vendorSelector`, else the process selector). Each request carries a `requestId` and its earlier attempts' `history` (`ProxyAttemptRecord`) on `ProxyAttemptRequest`, and outcomes carry the `requestId`.
- `ProxyResolutionOptions.gatewayOverrides` (`ProxyGatewayOverrides`, `ProxyGatewayEndpoint`) points a vendor at another gateway endpoint for assembly tests and the verification harness; it is not an env var or a policy field.
- **Breaking for telemetry consumers:** `ProxyResolutionSource` `"smartproxy-allocator"` becomes `"smartproxy-gateway"`; `ProxyCacheStatus` keeps only `"disabled"`; `SmartproxyAllocatorBodyClass`, the allocator timing fields and the per-attempt `poolIndex` (`i`) are no longer emitted, and `StealthTelemetrySink.recordPoolRefresh` and the stealth `poolRefreshes` field are removed. `ResolvedProxyConfig` gains `sticky`, `sessionId`, `expiresAt` and `lifetimeMinutes`. `PROXY_POOL_STALE` and `PROXY_POOL_EXHAUSTED` keep their codes and now mean the vendor edge refused a session and every session the attempt budget allowed.
- `ctx.http` now records a proxy attempt sample per policy-managed attempt, with the fields `ctx.stealth` records. `proxyHash` covers the vendor session id as well as the proxy host, so attempts on one gateway endpoint are told apart; NodeMaven hashes change value once.
- Ceremony egress lease handles are minted as `v2` (no `poolIndex` / `refreshEpoch`, optional `sessionId`); `v1` handles still verify and bind.
