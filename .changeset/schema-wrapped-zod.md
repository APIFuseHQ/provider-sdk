Public schemas describe themselves through the SDK; three schema lint rules retire (provider-sdk DX program, lane F, 2026-10-28). Level is `major` by the repository's API-report rule (the `fields.*()` option type is now the named `SensitivePresetOptions`, which rewrites existing report lines); the change is source-compatible for providers.

A node of an operation's public input or output (the root, each object property, each union branch and tuple item) is declared when it carries a `describeKey()` locale key, is a `kind.field()` handle, or is a `fields.*()` preset with its SDK-owned wording; `.optional()`, `.nullable()`, `.default()`, `.pipe()`, `z.lazy()` and array elements inherit from what they wrap. Raw `.describe("prose")` is the **deprecated** path for one release: `ZodType.describe` carries `@deprecated` hover text naming `.describeKey()`, `SensitiveFieldOptions.description` / `fields.*({ description })` likewise, and `defineProvider` logs one warning per provider listing every undeclared node with its reason (`raw .describe() prose` or `no description`) and the codemod. The next release refuses them at `defineProvider`. Nothing served changes: JSON Schema, descriptions, `x-apifuse-*` meta and redaction paths are byte-identical for every provider; the fleet (135 loadable checkouts) uses no raw prose.

Retired lint rules, deleted with their tests: `schema-description-raw-prose`, `schema-description-key-required` (both replaced by the deprecation above, DX rule 2: types and one runtime site over lint) and `sensitive-field-unmarked` (a field-name heuristic that guessed `token`/`phone`/`password` fields were secrets; no replacement, the declaration helpers are the source of truth). `description-key-required` stays one release: requiring `descriptionKey` on `OperationDefinition` is a one-line type change the fleet already satisfies (0 of 135 operations missing), but it touches 66 SDK test files edited by the other wave-2 lanes; it lands with the wave-3 release PR. `public-schema-upstream-field`, `public-schema-pinned-wire-field` and `public-schema-pinned-wire-field-stale` are unchanged.

One zod walker (`src/schema-walk.ts`: `schemaChildren`, `isSchemaNode`, `objectShape`, `schemaMeta`) now serves the handle contract resolver, the public field-name lint and the description check; the three private copies in `src/handle/contract.ts`, `src/lint.ts` and `src/public-schema-field-lint.ts` are gone. Edge kinds (`property`, `wrapper`, `element`, `entry`, `item`, `option`) are the only vocabulary; each consumer maps them to its own path and requirement rules.

Added: `collectUndeclaredFields(schema, side)` and the `UndeclaredField` / `UndeclaredFieldReason` types (the same check the runtime warning runs), `SensitivePresetOptions` (the options type of every `fields.*()` preset). `lintOperation` keeps its signature and no longer walks schemas.

Codemod: `bunx ast-grep scan -r node_modules/@apifuse/provider-sdk/scripts/codemods/schema.yml --update-all .` rewrites `name: <schema>.describe("prose")` to `.describeKey("schema.<name>")` and drops `fields.*({ description })`; each match prints the catalog entry to add. A `.describe()` with no enclosing property (a root, a union branch, a shared constant) is reported for a hand-written `describeKey(schema, key)`.
