Classify an expired stateful-forwarding deadline as its own observability category, `stateful_forwarding_deadline`, and adopt the platform's provider-observability taxonomy `2026-10-23`. When the `deadlineAt` a source pod forwards to the session owner pod has passed, the owner route serves `StatefulRoutingDeadlineError` as before: `504`, code `STATEFUL_FORWARDING_DEADLINE_EXPIRED`, source `apifuse`, `retryable: false`. Its `X-ApiFuse-Error-Observability` header and `provider_request_failed` log now carry category `stateful_forwarding_deadline` instead of `timeout`, so an APIFuse-side routing budget no longer counts as an upstream timeout. Status, code, source, retryability and the response body are unchanged, and an ordinary upstream timeout (`transport_timeout`, or a bare `504` through `categoryForStatus`) stays `timeout`.

`PROVIDER_OBSERVABILITY_TAXONOMY_VERSION` moves from `2026-08-07` to `2026-10-23`, and `PROVIDER_ERROR_CATEGORIES` (with the `ProviderErrorCategory` union) gains `stateful_forwarding_deadline`, mirroring the platform monorepo's `packages/provider-observability`. The error-observability header, the `provider_request_failed` log and the request telemetry header all report the new taxonomy version. Code that switches exhaustively over `ProviderErrorCategory`, or that pins the taxonomy version literal, needs the new member and value. The APIFuse gateway must accept taxonomy `2026-10-23` before providers ship this release: a gateway that does not know taxonomy `2026-10-23` discards the header category and falls back to the response body, which carries no category, so it records the deadline expiry by its `504` status as `upstream_http` with `retryable: true`.
